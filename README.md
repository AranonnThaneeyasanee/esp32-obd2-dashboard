# OBD2 Smart Dashboard

> จอแสดงผลข้อมูลรถยนต์ไฟฟ้าแบบเรียลไทม์ บน ESP32-S3 — อ่านข้อมูลจาก ECU ผ่าน OBD-II
> พร้อมเว็บพอร์ทัลในตัวสำหรับตั้งค่าและเปลี่ยนภาพเคลื่อนไหวจากมือถือ โดยไม่ต้องลงแอป

เสียบอุปกรณ์ OBD-II WiFi เข้าช่องใต้พวงมาลัย แล้วติดจอไว้ในรถ ระบบจะเชื่อมต่อเองอัตโนมัติ
ทุกครั้งที่สตาร์ทรถ แสดงความเร็ว อุณหภูมิแบตเตอรี่/มอเตอร์ SOC SOH และพลังงานที่ใช้ไป
พร้อมคำนวณค่าไฟของทริปนั้นเป็นเงินบาท

## ภาพรวมระบบ

```
        รถยนต์ (CAN bus)
              │
              │ OBD-II
              ▼
   ELM327 WiFi Adapter  ──(เป็น WiFi AP + TCP server :35000)
              │
              │  ESP32 ต่อเข้าไปในฐานะ STA
              ▼
┌─────────────────────────────────────────┐
│          ESP32-S3 Zero                  │
│                                         │
│  STA ──► TCP ──► ELM327 ──► PID Poller  │
│                                │        │
│                     ┌──────────┴──────┐ │
│                     ▼                 ▼ │
│              จอ ST7789         Web Portal│
│              320×172           (SoftAP)  │
└─────────────────────────────────────────┘
                                    ▲
                                    │ มือถือต่อเข้ามาตั้งค่า
```

จุดที่ท้าทายทางเทคนิคคือ ESP32 ต้องทำงาน **WiFi สองโหมดพร้อมกัน** ตลอดเวลา —
เป็น Station ไปเกาะ adapter ของรถ และเป็น Access Point ให้มือถือเข้ามาตั้งค่า
ทั้งหมดนี้บนชิปตัวเดียว RAM จำกัด และต้องไม่สะดุดขณะรถวิ่ง

### ความสามารถหลัก

| ด้าน | รายละเอียด |
|---|---|
| อ่านข้อมูลรถ | ความเร็ว, รอบมอเตอร์, อุณหภูมิแบตเตอรี่/มอเตอร์, SOC, SOH, ไฟ 12V |
| พลังงาน | คำนวณ kWh ที่ใช้/คืนกลับแบบ integrate ตามเวลาจริง แปลงเป็นค่าไฟบาท |
| หน้าจอ | 6 หน้าจัดเรียงเองได้ + หน้าหลักเลือกได้ระหว่าง GIF แอนิเมชันหรือ Robo Eyes |
| AutoBack | จอดนิ่ง 3 วินาทีสลับหน้าจออัตโนมัติ ขยับต่อแล้วกลับเอง |
| ประมาณเวลาชาร์จ | ตรวจจับการชาร์จเองจากทิศทางกระแส คำนวณเวลาจนถึง SOC เป้าหมาย |
| เว็บพอร์ทัล | ตั้งค่า + อัปโหลด GIF จากมือถือผ่าน captive portal ไม่ต้องลงแอป |

## ฮาร์ดแวร์

| ส่วนประกอบ | รุ่น / ขา |
|---|---|
| MCU | ESP32-S3 Zero (flash 4 MB) |
| จอแสดงผล | ST7789 IPS 172×320 — SCLK `12`, MOSI `11`, CS `10`, DC `9`, RST `8` |
| ปุ่มสัมผัส | TTP223 — SIG `7` |
| เชื่อมต่อรถ | ELM327 WiFi adapter (vGate / vLink / iCar และรุ่นที่ใช้โปรโตคอลเดียวกัน) |

จอต่อผ่าน hardware SPI ที่ 80 MHz เพื่อให้เล่น GIF ได้ลื่นโดยไม่กิน CPU

**การควบคุม** — ปุ่มสัมผัสปุ่มเดียว
- กดสั้น → เปลี่ยนหน้า
- กดค้าง 1.5 วินาที → สลับหน้าหลักระหว่าง GIF กับ Robo Eyes

## สถาปัตยกรรมซอฟต์แวร์

ทั้งระบบรันบน **superloop แบบ non-blocking** ไม่มี `delay()` ยาวในลูปหลักเลย
ทำให้เว็บเซิร์ฟเวอร์ การอ่าน OBD และการวาดจอ ทำงานสลับกันได้ลื่นบนคอร์เดียว

### ลำดับการทำงานใน `loop()`

```
dnsServer.processNextRequest()   ตอบ DNS ของ captive portal
server.handleClient()            ตอบ HTTP
 ├ pendingRestart guard          รีบูตที่เลื่อนไว้ (รอให้อัปโหลดจบก่อนเสมอ)
 ├ WiFi Supervisor               ตรวจสุขภาพ WiFi ทั้งสองโหมด
 ├ consume WiFi events           ดึง event จาก ISR ผ่าน critical section
 ├ AP watchdog                   ซ่อม SoftAP ถ้า mode/IP เพี้ยน
 ├ handleConnection()            ◄── หัวใจฝั่ง OBD
 └ แยกโหมด
    • มีมือถือต่ออยู่ → Setup Portal (จอโชว์ SSID/IP, ปิด GIF คืนหน่วยความจำ)
    • ไม่มี            → อ่านปุ่ม → ลอจิกชาร์จ/AutoBack → วาดจอ
```

### `handleConnection()` — state machine 3 ชั้น

**ชั้น 1 · STA Manager** — สแกนหา adapter แบบ async แล้วจัดลำดับผู้สมัคร

| ลำดับ | เงื่อนไข |
|---|---|
| 1 | SSID + BSSID ตรงกับที่เคยต่อสำเร็จ |
| 2 | SSID ตรง |
| 3 | ชื่อเข้าข่าย adapter (`obd`, `elm`, `vgate`, `vlink`, `icar`, …) |
| — | นอกเหนือจากนี้ **ตัดทิ้ง ไม่ลองต่อ** |

ไล่ต่อทีละตัวตามคิว มี timeout และ backoff ต่อติดแล้วจึงบันทึกค่าลง NVS

**ชั้น 2 · TCP + ELM Manager** — ต่อ TCP ไปที่ `:35000` แล้ว handshake ทีละขั้นแบบไม่บล็อก

```
ATZ → ATD → ATE0 → ATH1 → ATSP0 → ATAL → ATST64 → CONFIRMED
```

`ATE0` ปิด echo และ `ATH1` เปิด header ทำให้ข้อมูลที่ได้กลับมาเป็น raw CAN frame
พร้อม header ของ ECU ติดมาด้วย — จำเป็นสำหรับการแยกว่าคำตอบมาจาก ECU ตัวไหน

**ชั้น 3 · PID Polling Engine** — ยิงคำสั่งทีละตัวแบบ round-robin
รอจนได้ prompt `>` จึงยิงตัวถัดไป และ**เปลี่ยน ECU header เฉพาะเมื่อจำเป็น**
เพื่อลดรอบที่เสียเปล่า ค่าที่เปลี่ยนช้า (SOH, พลังงานสะสม) ถูกจัดเป็น slow query
ยิงทุก 2 วินาที ส่วนความเร็ว/กระแส วนเร็วตลอด

### การประเมินสุขภาพการเชื่อมต่อ

คำนวณครั้งเดียวต่อรอบ เป็น single source of truth ให้ทั้ง UI และ REST API

| สถานะ | เงื่อนไข |
|---|---|
| `CONNECTED` | WiFi + TCP + ELM ครบ และข้อมูลสดกว่า 3 วินาที |
| `WARNING` | ข้อมูลเก่า 3–5 วินาที หรือกำลังกู้การเชื่อมต่อ |
| `DISCONNECTED` | ข้อมูลเก่าเกิน 5 วินาที หรือลิงก์ขาด |

### การคำนวณพลังงาน

integrate `แรงดัน × กระแส × dt` โดยมี**จุด integrate เพียงจุดเดียว**ในระบบ
ซึ่งถูกกระตุ้นจากการอ่านค่ากระแสเท่านั้น — ออกแบบแบบนี้เพื่อกันการนับซ้ำ
ซึ่งเป็นบั๊กที่หาเจอยากมากในระบบที่มีหลาย PID อัปเดตไม่พร้อมกัน

ค่าพลังงานสะสมของทริป **จะไม่ถูกรีเซ็ต**ตอน WiFi หลุด ตอน TCP ต่อใหม่
หรือตอนผู้ใช้กดบันทึกตั้งค่า — รีเซ็ตได้ทางเดียวคือสั่งผ่าน `POST /reset_trip`

## เว็บพอร์ทัล

ESP32 เปิด SoftAP ชื่อ `OBD2-Dashboard` ค้างไว้ตลอด มือถือต่อแล้วหน้าตั้งค่าเด้งเอง
ด้วย DNS wildcard บวกกับ route ดักเฉพาะของแต่ละ OS (`/hotspot-detect.html` ของ iOS,
`/generate_204` ของ Android, `/ncsi.txt` ของ Windows)

พอมีมือถือต่อเข้ามา จอจะสลับเป็นหน้า Setup Portal ทันที พร้อมปิด GIF
เพื่อคืนหน่วยความจำให้ WiFi stack และหยุดการอ่าน OBD ชั่วคราวระหว่างอัปโหลด

### REST API

| Method | Path | หน้าที่ |
|---|---|---|
| `GET` | `/`, `/setup` | หน้าตั้งค่าหลัก |
| `GET` | `/api/status` | สถานะระบบ + ค่าตั้งทั้งหมด (JSON) |
| `POST` | `/save_config` | บันทึกค่าลง NVS — มีผลทันที ไม่ต้องรีบูต |
| `POST` | `/upload` | อัปโหลด GIF |
| `POST` | `/reset_trip` | รีเซ็ตพลังงานและค่าไฟของทริป |
| `POST` | `/api/restore_default_*` | คืนค่าภาพเริ่มต้น |

### ระบบอัปโหลด GIF

ESP32 มี RAM ไม่พอจะถอดรหัสและบีบอัด GIF เอง ระบบจึง**ย้ายงานหนักทั้งหมดไปทำบนมือถือ**
โดยฝัง GIF decoder และ encoder ไว้ในหน้าเว็บ

ฝั่งเบราว์เซอร์:

```
อ่านไฟล์ → ตรวจโครงสร้าง GIF และงบหน่วยความจำ
         → ถอดรหัสทุกเฟรม วาดลง canvas 320×172
         → รวมเฟรมที่ซ้ำกันเป๊ะ แล้วบวกเวลาหน่วงเข้าด้วยกัน
         → ไล่ลดคุณภาพทีละขั้นจนไฟล์ ≤ 200 KB
            64สี/ทุกเฟรม → 64สี/เว้น2 → … → 16สี/เว้น2
         → ตรวจไฟล์ผลลัพธ์อีกรอบก่อนส่ง (จำนวนเฟรม, ขนาด palette, ขนาดไฟล์)
         → อัปโหลด
```

ฝั่ง ESP32 ทำเป็น transaction ที่ย้อนกลับได้:

```
เขียนลงไฟล์ .tmp (ไม่แตะไฟล์จริง) → ตรวจขนาดและ header
  → ย้ายไฟล์เดิมเป็น .backup → ย้าย .tmp เป็นไฟล์จริง → ตรวจซ้ำ
  → ถ้าพลาดขั้นไหน คืนไฟล์เดิมจาก .backup ทันที
```

ไฟล์ภาพจึงมีชั้นสำรองถึง 4 ชั้น: ไฟล์ใช้งาน → ไฟล์สำรอง → ไฟล์ต้นฉบับใน
ระบบไฟล์ → ภาพฉุกเฉินที่ฝังอยู่ในเฟิร์มแวร์ ซึ่งลบไม่ได้

> หลังอัปโหลดภาพลูปสำเร็จ ระบบจะ**ยังไม่โหลดภาพใหม่ทันที** แต่รอจนมือถือตัดการเชื่อมต่อก่อน
> เพราะตอนนั้น WiFi stack ยังจองหน่วยความจำอยู่ การโหลดทันทีเสี่ยงหน่วยความจำไม่พอ

## ความทนทานของระบบ

ส่วนที่ใช้เวลาพัฒนามากที่สุดคือการทำให้ระบบ "ไม่ค้าง" ในสภาพการใช้งานจริง
เพราะอุปกรณ์อยู่ในรถ ไม่มีใครมากดรีเซ็ตให้

| กลไก | แก้ปัญหาอะไร |
|---|---|
| **Dual-slot NVS + CRC** | เก็บค่าตั้ง WiFi สองชุดสลับกันเขียน แต่ละชุดมี checksum และหมายเลขรุ่น ถ้าไฟดับขณะเขียน ยังมีชุดเดิมที่สมบูรณ์ให้ใช้ |
| **AP watchdog** | SoftAP หลุดหรือ IP เพี้ยน ซ่อมคืนโดยไม่กระทบการเชื่อมต่อฝั่งรถ |
| **Global WiFi guard** | ถ้า WiFi ตายทั้งสองโหมดต่อเนื่องเกิน 2 นาที จึงรีบูต — และยกเลิกทันทีถ้ามีสัญญาณฟื้น |
| **Preserve-first recovery** | ตอนออกจากหน้าตั้งค่า ถ้าการเชื่อมต่อกับรถยังดีอยู่ **ห้ามแตะ** ซ่อมเฉพาะส่วนที่พังจริง |
| **GIF startup recovery** | ตรวจและกู้ไฟล์ภาพที่ค้างจากการอัปโหลดที่ถูกขัดจังหวะ ตั้งแต่ตอนบูต |
| **Deferred restart** | การรีบูตทุกกรณีถูกเลื่อนจนกว่าจะแน่ใจว่าไม่มีการอัปโหลดค้างอยู่ |

ทุกการเปลี่ยนสถานะสำคัญถูก log ออก Serial พร้อม timestamp และตัวนับ
เพื่อให้ไล่ปัญหาย้อนหลังจากการใช้งานจริงได้

## การ build และทดลองใช้

ต้องมี [PlatformIO](https://platformio.org/)

```bash
git clone https://github.com/<user>/<repo>.git
cd <repo>

# คอมไพล์
pio run -e esp32s3-dashboard

# แฟลชลงบอร์ด + อัปโหลดไฟล์ภาพลง LittleFS
pio run -e esp32s3-dashboard -t upload
pio run -e esp32s3-dashboard -t uploadfs
```

### ทดลองโดยไม่ต้องมีรถ

ในโปรเจคมีตัวจำลอง OBD2 adapter ให้ (`S3_Zero_OBD2_Simulator.ino`)
แฟลชลง ESP32 อีกบอร์ดหนึ่ง มันจะปล่อย WiFi และเปิด TCP server ที่พอร์ต 35000
ตอบคำสั่ง ELM327 พร้อมข้อมูลรถจำลองที่ขยับไปมาเหมือนขับจริง

บอร์ดหลักจะหาเจอและเชื่อมต่อเองอัตโนมัติ — เห็นระบบทำงานครบทุกส่วนได้บนโต๊ะ

### เข้าหน้าตั้งค่า

ต่อ WiFi ชื่อ `OBD2-Dashboard` รหัส `12345678` แล้วหน้าตั้งค่าจะเด้งเอง
ถ้าไม่เด้งให้เปิดเบราว์เซอร์ไปที่ `192.168.4.1`

## ค่า calibration เฉพาะรุ่นรถ

ข้อมูลที่รถส่งกลับมาเป็นเลขดิบ ต้องรู้ว่า PID ไหนอยู่ที่ ECU ตัวใด ข้อมูลอยู่ไบต์ไหน
และต้องคูณหารเท่าไหร่ถึงจะได้หน่วยจริง ซึ่ง**ผู้ผลิตแต่ละรายไม่เปิดเผย**

ค่าเหล่านี้ในโปรเจคได้มาจากการเก็บ log ขณะขับทดสอบบนถนนจริง แล้ววิเคราะห์หา
ความสัมพันธ์ระหว่างค่าดิบกับค่าที่วัดได้ ถือเป็นทรัพย์สินทางปัญญาของผู้พัฒนา
**จึงไม่ได้เผยแพร่พร้อมซอร์สโค้ดชุดนี้**

โค้ดที่เห็นเป็นโค้ดจริงทั้งหมด ไม่มีส่วนใดถูกตัดออก — ค่าตัวเลขถูกย้ายไปรวมไว้ที่
[`src/vehicle_calibration.example.h`](src/vehicle_calibration.example.h) ซึ่งใส่ค่าตัวอย่างไว้แทน

```
#if __has_include("vehicle_calibration.h")
  #include "vehicle_calibration.h"          ← ค่าจริงของคุณ (ถ้ามี)
#else
  #include "vehicle_calibration.example.h"  ← ค่าตัวอย่าง
#endif
```

ผลที่ตามมา:

- โปรเจค **คอมไพล์ผ่านและรันได้ทันที** ที่ clone มา
- ใช้กับ**ตัวจำลอง**ได้ครบทุกฟังก์ชัน เพราะตัวจำลองตอบตามค่าตัวอย่างชุดเดียวกัน
- โหมด **EV Generic / ICE Generic** ใช้ PID มาตรฐาน OBD-II (SAE J1979) ซึ่งเป็น
  สเปคสาธารณะ จึงใช้กับรถทั่วไปได้จริงโดยไม่ต้องตั้งค่าอะไร
- ถ้าต้องการใช้กับรถ EV รุ่นเฉพาะ ให้คัดลอกไฟล์ `.example.h` เป็น
  `vehicle_calibration.h` แล้วใส่ค่าของรถคุณเอง

> คณะกรรมการที่ต้องการตรวจสอบค่าจริงหรือดู log การทดสอบ ติดต่อผู้พัฒนาได้โดยตรง

## โครงสร้างไฟล์

```
src/
├── main_s3_dashboard.cpp          จุดเริ่ม: setup/loop, route เว็บ, ลอจิก AutoBack และการชาร์จ
├── obd_handler.h                  state machine ของ STA/TCP/ELM, PID poller, ตัวแปลงข้อมูล
├── dashboard_config.h             ตัวแปรร่วม, enum สถานะ, โปรไฟล์รถ, ค่าคงที่ของระบบ
├── ui_themes.h                    การวาดหน้าจอทุกหน้า + การไหลของตัวเลข (EMA)
├── gif_player.h                   เล่น GIF พร้อมระบบสำรองหลายชั้น
├── web_handlers.h                 transaction การอัปโหลดไฟล์และการกู้คืน
├── web_portal_html.h              หน้าเว็บทั้งหมด (ฝัง GIF encoder/decoder ไว้ในตัว)
├── touch_handler.h                อ่านปุ่มสัมผัส แยกกดสั้น/กดค้าง
├── vehicle_calibration.example.h  ค่าตัวอย่างเฉพาะรุ่นรถ
└── main_c3.cpp                    เฟิร์มแวร์บอร์ดอ่านแรงดัน (ออปชัน)

data/                              ภาพเริ่มต้นที่เขียนลง LittleFS
S3_Zero_OBD2_Simulator.ino         ตัวจำลอง OBD2 adapter สำหรับทดสอบ
```
